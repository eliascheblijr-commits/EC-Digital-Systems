Gym Guardian Architecture

Technical protections and system hardening from Schedule B of the Gym Guardian agreement.

Data integrity

Blockchain-style transaction protection.

Gym Guardian relies on cryptographic verification to ensure ledger integrity and to guard against out-of-band database tampering.

HMAC-SHA256 ledger chain

Each transaction row is linked by an HMAC-SHA256 hash sequence. Direct database modification breaks the sequence and locks administrative access.

Idempotency firewall

State-mutating endpoints enforce single-use UUIDv4 tracking keys to block duplicate actions from double-submits or network retries.

Authentication

Session hardening and access control.

Role-based control

Strict permission mapping ties endpoints to specific clearance levels.

JWT mobility

API and mobile clients use secure JWTs instead of browser session cookies.

Secure cookies

Sessions are protected with httponly, secure, and samesite=Lax cookie policies.

Multi-tenant scoping

All operations validate the assigned gym_id to prevent cross-tenant access.

Defenses

Active protections against common web threats.

SQL Injection protection

All database access is implemented through PDO prepared statements. Variable concatenation in SQL is prohibited.

XSS prevention

Dynamic frontend output is encoded with htmlspecialchars() to block malicious script injection.

CSP headers

Default source restrictions and inline script blocking are enforced by a defensive Content Security Policy.

CSRF mitigation

All state-changing forms and links validate cryptographically secure tokens to stop cross-site request forgery.

Infrastructure

Caching, concurrency, and server hardening.

Redis caching

High-performance Redis is used for request deduplication and to preserve transactional integrity under load.

Row-level locking

Pessimistic SELECT ... FOR UPDATE locking prevents race conditions in high-volume member check-ins.

Secure headers

Production enforces X-Frame-Options, X-Content-Type-Options, and HSTS to reduce clickjacking and protocol abuse.

Audit visibility

Basic staff visibility and reconciliation modules are designed to capture desk errors and maintain accountability.

Data lifecycle

Soft deletes, retention, and minimization.

The system enforces soft-delete architecture with a three-day recovery grace period, followed by safe automated cleanup to satisfy regional data protection requirements.
